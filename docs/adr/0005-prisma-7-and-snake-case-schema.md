# 0005 Prisma 7, snake_case tables, database-generated IDs

Status: accepted (V1).

## Context
On 2026-10-24 npm `latest` for `prisma` is `8.0.0-rc.27`, a release candidate; `@prisma/adapter-pg` latest is `7.10.1`. The worker writes SQL by hand with sqlx. Prisma's default names (`"Job"`, `"runAfter"`) must be quoted in SQL, and `user` and `references` are reserved words. `@default(cuid())` is generated by the Prisma client, so rows the worker inserts would need their own ID code.

## Decision
- Pin Prisma 7.10.x (`prisma`, `@prisma/client`, `@prisma/adapter-pg`) with the `prisma-client` generator and `prisma.config.ts`. Revisit Prisma 8 after V1 ships.
- Map every model and column to snake_case with `@@map` / `@map`. The Better Auth user table is `app_user`; the CVE URL list is `reference_urls`.
- App table IDs: `@default(dbgenerated("gen_random_uuid()::text"))`.
- Enums are Postgres enums (`job_type`, `device_status`, …), read in Rust with `sqlx::Type`.
- The worker uses runtime `sqlx::query` / `query_as`, never the `query!` macros, so it builds without a database. It never runs DDL (CI greps for it).

## Consequences
- Worker SQL is plain and readable. Prisma code still uses camelCase names.
- `@updatedAt` is client-side. The worker does not write `device.updated_at`, which therefore means "last edited by the user".
- Upgrading to Prisma 8 later is a separate PR with its own migration check.
- Better Auth schema changes (plugins later) must keep the `@map` names; regenerate with the Better Auth CLI and re-apply them.
